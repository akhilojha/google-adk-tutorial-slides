Two ways to add that tool
🔧
Option A: write a FunctionTool
You can write postToAtlassian() as a Java method — FunctionTools can read and write. But now you own the Atlassian REST client, auth tokens, API versioning, pagination, and error handling. That's a project, not a tool.
✅
Option B: use an MCP server
Atlassian ships an official MCP server covering Confluence and Jira. Connect to it and you get create_page, update_page, search_pages — zero implementation code. The real difference is ownership, not capability.
CODE  ·  Three lines to wire an MCP server into the existing agent

Adding MCP to TripPlannerAgent

java TripPlannerAgent.java 
// 1. Create the MCP toolset — ADK spawns the server process
StdioServerParameters mcpParams = StdioServerParameters.builder()
    .command("uvx")
    .args(List.of("mcp-atlassian"))
    .env(Map.of(
        "ATLASSIAN_URL",   System.getenv("ATLASSIAN_URL"),
        "ATLASSIAN_TOKEN", System.getenv("ATLASSIAN_TOKEN")
    ))
    .build();

McpToolset atlassianTools = new McpToolset(mcpParams.toServerParameters());

// 2. Pass it alongside the existing FunctionTools — nothing else changes
public static final LlmAgent ROOT_AGENT = LlmAgent.builder()
    .name("trip-planner-agent")
    .description("Plans trips and publishes summaries to Atlassian")
    .instruction("You are a helpful trip planning assistant.")
    .model(MODEL_NAME)
    .tools(
        FunctionTool.create(TripPlannerAgent.class, "getCountryInfo"),
        FunctionTool.create(TripPlannerAgent.class, "getCityCoordinates"),
        FunctionTool.create(TripPlannerAgent.class, "getWeather"),
        atlassianTools  // ← MCP toolset slotted in like any FunctionTool
    )
    .build();
✅
Zero new Java tool methods
create_page, update_page, search_pages — all from the Atlassian MCP server. The only change to TripPlannerAgent is adding atlassianTools to .tools().

THEORY  ·  Model Context Protocol

What is MCP?

An open standard for tool exposure
MCP is a protocol — a wire format — that lets a server advertise tools (with names, descriptions, and JSON input schemas) and let an agent client discover and call them at runtime.
Not a framework, not a library
Any process that speaks the MCP protocol is an MCP server. Atlassian, GitHub, Slack, and hundreds of others already publish servers. Your agent connects to them without knowing anything about their internals.
The LLM never knows the difference
ADK calls tools/list on the MCP server and converts each result into a FunctionDeclaration — the same type that FunctionTool produces. The LLM sees identical JSON schemas either way.
💡
Think of it like a REST API, but for tools
A REST API exposes endpoints. An MCP server exposes tools. Instead of GET /users you get get_users. Instead of reading API docs, the agent reads the schema at connection time.
🔌
Two transport modes
stdio — ADK spawns a child process (e.g. uvx mcp-atlassian). Tight coupling, no network.

SSE / HTTP — ADK connects to a running server over the network. Shared, multi-agent, remotely hosted.
DEEP DIVE  ·  What happens before the first user message

MCP Startup Sequence

🔌
Startup is one-time
tools/list runs once when McpToolset is constructed — not on every request. The discovered schemas are cached and sent with every LLM call for the lifetime of the agent.
💡
FunctionDeclaration is the bridge
ADK normalises MCP tool schemas into FunctionDeclaration — the same internal type that FunctionTool produces. From the LLM's perspective, there is no difference.
⚠️
AutoCloseable — always close it
McpToolset owns the spawned process or connection. If you don't close it, the Node.js process stays alive after your agent finishes. Use try-with-resources.

PRODUCTION  ·  Atlassian's official hosted MCP endpoint

Atlassian Remote MCP

Step 1 — Create an OAuth 2.0 app
1
Go to developer.atlassian.com
Create a new OAuth 2.0 (3LO) app. Add scopes: read:confluence-content.all, write:confluence-content.
2
Authorize and get an access token
Complete the OAuth flow to obtain a Bearer token scoped to your Atlassian workspace.
3
Connect via SseServerParameters
Pass the token as an Authorization header — no Python, no local process.
Step 2 — Wire it into ADK
java SseServerParameters — Atlassian hosted MCP 
String token = System.getenv("ATLASSIAN_OAUTH_TOKEN");

McpToolset atlassianTools = new McpToolset(
    SseServerParameters.builder()
        .url("https://mcp.atlassian.com/v1/sse")
        .headers(Map.of("Authorization", "Bearer " + token))
        .build()
);

// Plug in exactly like the stdio version — nothing else changes
LlmAgent.builder()
    .tools(..., atlassianTools)
    .build();
✅
No Python, no uvx, no process
Atlassian runs the MCP server. Your JVM just opens an SSE connection. No local install, no process lifecycle to manage.
🌐
Shared across all agent instances
One hosted endpoint serves every agent. Scale horizontally without spinning up more MCP processes per pod.
⚠️
OAuth vs API token
This endpoint requires OAuth 2.0 — not the simple API token used with uvx mcp-atlassian. More setup, but the right model for production services.
🔁
stdio → SSE: one line change
Swap StdioServerParameters for SseServerParameters. The rest of your agent — tools, instructions, runner — is untouched.
03  ·  Key Takeaways

What you learned

MCP is a wire protocol
Not a library, not a framework — a protocol. Any server that speaks MCP can give your agent tools. ADK handles the handshake, discovery, and proxying.
McpToolset = tool discovery + proxy
On construction: calls tools/list, converts results to FunctionDeclaration[]. On tool call: proxies tools/call to the server and returns the result to ADK.
LLM sees no difference
Both FunctionTool and MCP tools produce FunctionDeclaration. The model reads identical JSON schemas — it has no idea which path executes the tool.
stdio vs SSE
stdio spawns a child process per agent (local dev). SSE connects to a shared remote server (production). Same API — swap StdioServerParameters for SseServerParameters.
Mix Java + MCP in one agent
Pass both to .tools(). The LLM chains them freely. In TripPlannerAgent: 3 Java tools read data, 1 MCP toolset writes to Atlassian — zero routing code.
Always close McpToolset
McpToolset implements AutoCloseable. Wrap it in try-with-resources. Not closing it leaks the spawned process for the lifetime of the JVM.
