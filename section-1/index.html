LOCAL MODELS  ·  Why run LLMs locally

What is a Local LLM?

A model that runs entirely on your machine — no internet, no API key, no per-token cost.

🔒  Privacy
Data never leaves your machine. No cloud dependency for sensitive workloads.
💸  Zero cost
No API bills. Iterate freely during development without watching token spend.
✈️  Offline
No internet required. Works anywhere, including air-gapped environments.
⚡  No rate limits
Experiment at full speed. No throttling, no quota waiting.
LM STUDIO  ·  lmstudio.ai — free, Mac / Windows / Linux

Setting Up LM Studio

1
Download & open LM Studio
Mac, Windows, Linux. Free at lmstudio.ai
2
Model Search tab → search for a model
Recommended: qwen/qwen3.5-9b or google/gemma-4-e4b
3
Download → Load → Developer tab → Start Server
Server starts at http://localhost:1234
4
Verify
curl http://localhost:1234/v1/models → JSON with the loaded model name
🔌
Why it works with ADK
LM Studio exposes an Anthropic-compatible /v1/messages endpoint — ADK's built-in Claude adapter works with it directly, just pointed at localhost.
LOCALLLM  ·  Wiring ADK to LM Studio

The LocalLLM Class

java src/main/java/llm/LocalLLM.java 
public class LocalLLM extends Claude {

    private static final String BASE_URL = "http://localhost:1234";

    public LocalLLM(String modelName) {
        super(modelName, AnthropicOkHttpClient.builder()
                .baseUrl(BASE_URL)
                .apiKey("lm-studio")  // value ignored by LM Studio, field is required
                .build());
    }
}

// Register in a static block — runs before ROOT_AGENT is initialised
static {
    LlmRegistry.registerLlm(
        "local/.*",               // regex — matches any "local/..." string
        modelName -> new LocalLLM(modelName)
    );
}

// Use it
LlmAgent.builder()
    .name("my-agent")
    .model("local/qwen2.5-7b-instruct")  // matched by the regex above
    ...
ALTERNATIVELY  ·  Cloud model

Gemini — One Line Swap

No LocalLLM class, no registry. Change the model string. That's it.

1 — Create a .env file in your project root
bash terminal — MacOS / Linux 
echo 'export GOOGLE_API_KEY="YOUR_API_KEY"' > .env
2 — Source it before running
bash 
source .env
3 — Change one line in your agent
java 
LlmAgent.builder()
    .name("my-agent")
    .model("gemini-2.0-flash")  // ← only change needed
    ...                             // everything else identical

PRODUCTION  ·  ApigeeLlm — enterprise LLM gateway

Multi-Model in Production

One agent endpoint → Apigee → any model. Auth, rate limits, routing, and logging enforced centrally.

java 
ApigeeLlm llm = ApigeeLlm.builder()
    .modelName("apigee/gemini-2.5-flash")
    .proxyUrl("https://<org>.apigee.net/llm/v1")
    .build();

LlmAgent.builder()
    .name("my-agent")
    .model(llm)
    ...
💡
One endpoint, any model
Your agent code never changes when swapping providers. Apigee proxy config controls routing — not Java code.
⚠️
Wire format is Gemini
ApigeeLlm uses the Gemini API format end-to-end. Apigee must transform requests for non-Gemini backends (Claude, OpenAI).
VERIFY  ·  AdkWebServer — dev UI from google-adk-dev

Running the Agent

AdkWebServer scans your compiled classes, finds agents, and exposes a chat UI + REST API.

Start the server
bash 
mvn compile exec:java \
    -Dexec.mainClass="com.google.adk.web.AdkWebServer" \
    -Dexec.args="--adk.agents.source-dir=target --server.port=8000"
What the flags mean
FlagWhat it does
source-dir=target Where to scan for compiled agent classes — Maven outputs to target/
server.port=8000 Port for the embedded Spring Boot web server
How it finds your agent
Walks all .class files under source-dir
Loads each via URLClassLoader + reflection
Looks for public static BaseAgent ROOT_AGENT
Registered name = agentInstance.name()
No special package, annotation, or interface needed
⚠️
Dev only
Lives in google-adk-dev. Not for production — remove the dependency before deploying.
